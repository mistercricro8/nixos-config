Distribute the project tasks among the team members (check previous assignments for the member list).

Shuffle the members randomly before assigning (use code with today's date as seed), so roles don't always fall on the same people.

Keep the following guidelines in mind:
    Self-contained "one-and-done" work: split the project into monolithic pieces (e.g., full report, entire slides, standalone tool/script) so each person can finish their part alone, without going back and forth or waiting on reviews. Avoid having multiple people edit the same file.
    Direct task-to-task dependencies only: list dependencies only as what teammate output is needed first (e.g., "Blocked by: Member X's dataset" or "Can start immediately"). Don't consider outside dependencies like guides or rubrics.
    No extra sections or filler: output only the member breakdowns, nothing else.

Write each Description for an AI agent who will do the work, in plain everyday language:
    Don't give exact step-by-step instructions, file paths, or technologies.
    Say what the task is about in simple words.
    Tell them to first look at the current state and understand it.
    Tell them to then ask the user questions (what worries them, what style they prefer) before deciding anything.
    Tell them to propose at least three different options, compare them, and pick one themselves with a simple reason why.
