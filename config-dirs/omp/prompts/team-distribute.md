Distribute the project tasks among the team members (check previous assignments for the member list).

Keep the following guidelines in mind:
    Self-contained "one-and-done" work: Subdivide the project into monolithic deliverables (e.g., full report, entire slides, standalone tool/script) so each person can execute their part from start to finish without cyclic back-and-forth, intermediate review gates, or multi-phase handoffs. Avoid having multiple people edit the same file to prevent merge conflicts.
    Direct task-to-task dependencies only: List dependencies strictly in terms of what member output is required before starting (e.g., "Blocked by: Member X's dataset" or "Can start immediately"). Do not mention external dependencies like classroom guides, papers, or course rubrics.
    Keep the thorough, technical descriptions: Detail exactly what each member must implement or write, including paths/technologies where relevant.
    No extra sections or filler: Output only the member breakdowns. Do not include introductory notes, reference document sections, technical specification annexes, or sign-off/QA steps.

For each member, provide:
    Member Name
    Assigned Module / Role
    Description of Responsibilities (concrete, end-to-end scope)
    Deadline (Submission deadline is XXXXX)
    Dependencies (only predecessors/successors among team members)
